# 泳道拆样台(fastq-demux)

测序中心同一泳道的 R1 / R2 / I1 三份**未压缩** FASTQ,按样本索引 CSV 拆出成对读段。
FastAPI + SQLite,逐对流式处理,不整份读入内存。

## 启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

本地开发(不需要 Docker):

```bash
pip install -r requirements.txt
uvicorn app.main:app --port 8000
# 测试:pip install httpx pytest && python -m pytest tests/
```

## 使用

1. 首页填**运行号**(字母数字开头,可含 `- _ .`),上传 R1、R2、I1 三份未压缩 FASTQ
   和样本索引 CSV。
2. CSV 两列:`样本号,索引序列`;首行可为表头;索引仅允许 ACGTN(不区分大小写),
   必须**等长且唯一**;样本号唯一,且不能叫 `undetermined`(保留给未分配组)。
3. 提交后页面每 3 秒自动刷新;处理完成后按组提供 `样本_R1.fastq` / `样本_R2.fastq`
   下载、每组对数(含其中纠错对数)和处理日志 `demux.log`。

## 拆分规则

- 逐对核对:R1/R2/I1 三条记录的**读段号**(头部第一个空白前)必须一致,
  每条记录的**序列与质量长度**必须一致;三份文件记录数必须相同。
- 索引**精确匹配优先**;无精确匹配时,仅当**单碱基错配候选唯一**才纠到该样本;
  候选多个或无候选一律进 `undetermined`(未分配组)。
- 各组输出严格保持输入顺序;只输出 R1/R2(I1 仅用于判定)。

## 可靠性设计

- **不发布半套文件**:处理中的上传件与输出都在 `data/staging/<随机目录>/`;
  全部写完并生成日志后,输出目录经 `os.rename` **原子**移到
  `data/published/<运行号>/`,同一事务写入计数并把运行置为 `published`。
  后段损坏、磁盘写失败等任何异常都会把运行标为 `failed` 并清理半成品。
- **发布时登记内容依据**:发布前对每组 R1/R2 流式计算字节数与 SHA-256,
  连同记录数写入 `published_files`,与计数同事务提交。
- **重启核验**:启动时对每个已发布运行重新核验。任一组文件缺失、字节数
  少于发布值(截断)或 SHA-256 不符(含**等长内容改写**)都会把该次运行
  标为失败,目录移入 `data/quarantine/` 停止供数;页面说明原因,不再展示
  分组对数与下载。单个运行损坏不影响其他已发布运行。
- **下载前核验**:每次下载前对整个运行做同样核验,发现任何一组损坏就停止
  整次运行供数(不会只返回"看起来正常"的某个文件)。因此下载前会重新读取
  该运行的全部已发布文件,数据量很大时下载启动会相应变慢。
- **旧库运行**:发布时没有内容摘要的历史运行,按 FASTQ 结构、R1/R2 读段号
  配对和入库对数核验;页面明确标注"无法追溯等长内容改动",不会冒充能识别
  它们。旧库中声明过有摘要但摘要丢失的运行直接判失败,不悄悄降级。
- **大文件**:摘要计算与结构核验都按固定大小分块/逐记录流式读取,内存占用
  与 FASTQ 大小无关。
- **进程中断恢复**:启动时把残留的 `processing` 运行标为 `failed`,
  清掉其暂存目录和可能来不及落库的发布目录;无主的暂存目录一并清理。
- **重试与不可改写**:失败/中断/核验失败的运行可用同一运行号重新提交直到
  完成,重新上传后重新建立内容摘要并恢复供数;已发布运行同号提交返回 409,
  文件不会被覆盖。

## 已知限制

- 仅支持未压缩的 4 行 FASTQ(不支持 .gz、不支持序列折行);上传 gzip 会以
  "不是纯文本"失败,需先解压。
- 单进程单 worker 运行(后台线程处理);不要起多个 uvicorn worker,
  否则中断恢复会误判在途运行。
- 完整性摘要按运行保存在同一 SQLite 库中;若数据库与 `published/` 目录被分别
  恢复/回滚到不一致的版本,校验会判失败而非放行。整卷一起备份即可。
- 启动时会重新核验全部已发布数据(流式计算摘要)。发布数据量很大时首次
  就绪会相应变慢,这是"重启即发现损坏"的代价;内存占用不随文件大小增长。
- 核验失败的发布目录移到 `data/quarantine/` 留档,便于排查;确认无需保留后
  可手动清理。
- 旧库中从未登记摘要的运行无法识别发布后的等长内容改写(不追溯历史);
  需要该保证时用同一运行号重新上传一次。
- 每个样本 + 未分配组各占用 2 个输出文件句柄,样本数极多(数千)时需调高
  进程 fd 上限。
- 索引读长与样本索引长度不一致的读段进未分配组(不报错,见日志与计数)。

## 目录结构

```
app/
  main.py      # 路由、后台处理、原子发布、启动恢复与发布前核验
  integrity.py # 发布内容摘要、流式摘要重算与结构核验
  demux.py     # 逐对流式 FASTQ 解析与拆分核心
  samples.py   # 样本索引 CSV 解析校验
  db.py        # SQLite schema、旧库补列与连接
  config.py    # DATA_DIR 路径
  templates/   # 页面
tests/test_app.py  # 关键情形自测(pytest)
data/          # 运行期生成:app.db、staging/、published/、quarantine/
```
